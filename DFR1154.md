# DFRobot DFR1154 Kamera

Der DFR1154 laeuft als eigenes PlatformIO-Ziel. Der vorhandene AI-Thinker-Build bleibt davon getrennt.

## Funktionen

- OV3660 JPEG-Kamera mit 8 MB PSRAM
- MJPEG ueber RTSP auf Port 8554
- MQTT-Steuerung und dauerhafte Statusmeldungen
- Arduino OTA nach dem ersten USB-Upload
- SD-Zeitraffer, standardmaessig alle 60 Sekunden
- Speicherstopp bei 22 GB oder 95 Prozent einer kleineren SD-Karte
- LTR-308-Lichtsensor und IR-Modi `aus`, `an`, `automatisch`
- BME280 fuer Temperatur, Luftfeuchte und Luftdruck ueber den Gravity-Anschluss
- Victron SmartSolar MPPT Livewerte ueber verschluesselte BLE Instant Readouts
- Geschuetztes HTTP-Archiv auf Port 8080

Audio und Mikrofon werden aktuell nicht initialisiert.

## Erster Build und USB-Upload

```powershell
platformio run -e dfr1154
platformio run -e dfr1154 -t upload
platformio device monitor -b 115200
```

Fuer spaetere OTA-Uploads:

```powershell
platformio run -e dfr1154_ota -t upload
```

## BME280

Der BME280 verwendet einen eigenen I2C-Bus, damit Kamera und LTR-308 auf
GPIO8/9 unveraendert weiterlaufen.

| BME280 | DFR1154 V1.1 Gravity |
| --- | --- |
| VCC | + (3,3 V Ausgang) |
| GND | - |
| SDA / D | GPIO43 |
| SCL / C | GPIO44 |

Die Adressen `0x76` und `0x77` werden automatisch erkannt. Der Gravity-Pluspin
der V1.1 darf nicht mit einer externen Spannungsquelle verbunden werden.

MQTT unterhalb von `camera/dfr1154-cam-01`:

- `status/bme280`: `ready`, `stale`, `unavailable`, `bus_error` oder `disabled`
- `sensor/bme280/temperature_c`
- `sensor/bme280/humidity_percent`
- `sensor/bme280/pressure_hpa`
- `sensor/bme280/json`: alle aktuellen Werte als JSON

## Victron SmartSolar ueber BLE

Die Firmware liest passive, verschluesselte Instant-Readout-Advertisements. Sie
baut keine dauerhafte Bluetooth-Verbindung zum MPPT auf. Dadurch kann sie die
Livewerte regelmaessig empfangen, solange VictronConnect nicht aktiv mit dem
Regler verbunden ist.

In VictronConnect:

1. SmartSolar verbinden und `Product info` oeffnen.
2. `Instant readout via Bluetooth` aktivieren.
3. Unter `Instant readout details` auf `Show` tippen.
4. MAC-Adresse und den 32-stelligen Encryption Key in `dfr1154_config.h` bei
   `kVictronMac` und `kVictronEncryptionKey` eintragen.

Ohne diese Werte startet die Kamera normal und meldet auf
`status/victron_ble` den Zustand `not_configured`. Weitere Zustaende sind
`waiting`, `ready`, `stale`, `init_error` und `disabled`.

Victron-MQTT-Topics:

- `victron/mppt/charger_state` und `charger_state_id`
- `victron/mppt/error_code`
- `victron/mppt/battery_voltage_v` und `battery_current_a`
- `victron/mppt/panel_power_w`
- `victron/mppt/yield_today_wh`
- `victron/mppt/load_current_a`
- `victron/mppt/rssi` und `age_seconds`
- `victron/mppt/json`: alle aktuellen Werte als JSON

Die SD-Karte muss FAT32 formatiert sein. DFRobot nennt 32 GB als maximal unterstuetzte Kartengroesse.

## MQTT

Basis-Topic: `camera/dfr1154-cam-01`

- `cmd/start`, `cmd/stop`, `cmd/restart`, `cmd/ping`
- `cmd/set` fuer Kamera, IR und Zeitraffer
- `cmd/timelapse/start`, `cmd/timelapse/stop`, `cmd/timelapse/set`

Beispiel:

```json
{
  "framesize": 2,
  "jpeg_quality": 10,
  "stream_fps": 10,
  "ir_mode": 2,
  "ir_on_lux": 5,
  "ir_off_lux": 10,
  "timelapse_enabled": true,
  "timelapse_interval_seconds": 60,
  "timelapse_limit_gb": 22
}
```

## HTTP-Archiv

Der Header `X-Archive-Token` muss dem Wert in `dfr1154_config.h` entsprechen.

- `GET /api/health`
- `GET /api/timelapse`
- `GET /api/timelapse/file?name=frame-....jpg`
- `DELETE /api/timelapse/file?name=frame-....jpg`
- `DELETE /api/timelapse` loescht alle Zeitraffer-JPEGs
